# Brovim audit and five-hour change list

Reviewed on November 8, 2026. The five-hour Git-history window is approximately 18:07–23:07 UTC; the
working changes below were made during the current audit. This report covers the extension's
background services, completion engines, keyboard/content scripts, UI pages, settings and backups,
manifest/resources, packaging, and Helium setup script.

## Changes already committed and pushed

### Tab switching and preview retention — `98e7b900` (21:41 UTC)

- Keep unchanged card elements and decoded thumbnails across reopening, reordering, resizing and
  closing tabs. Update changed titles and their accessibility labels without rebuilding the images.
- Look up thumbnail cards by tab ID instead of repeatedly scanning the grid.
- Request only previews missing from the initial cached response; avoid another thumbnail request
  after every tab close.
- Decode replacement images asynchronously before showing them. Retain the previous preview or
  letter tile if decoding fails.
- Release pending tab-list/thumbnail reads when an opening is cancelled or replaced, and ignore
  obsolete responses. Cancelled startup work cannot reopen an old grid.
- Reuse the text segmenter used to create letter tiles.
- Raise preview retention from 5 by default/10 maximum to **15 by default**, with choices of 30 or
  50. Keep the existing **6 MiB** image-data cap and separation between normal and private previews.
- Upgrade old 5/10-preview settings to 15. Preserve older backup limits by mapping them to the
  supported choices. Verify retention after cache reloading and trimming when lowering the limit.
- Update Options, documentation, and regression tests for these behaviors, including a 200-tab grid
  and navigation while previews decode.

Commit:
[98e7b900](https://github.com/MR-5OBOT/brovim/commit/98e7b90006af64466bbef63b64a00cbc42f5f508).

### Native-dark-theme exclusions — `8d1d1ace` (22:38 UTC)

- Prefill “Never darken” with 21 domains covering Gmail, WhatsApp Web, YouTube, GitHub, Reddit,
  Discord, Telegram Web, X/Twitter, Facebook, Messenger, Instagram, Twitch, Spotify, Wikipedia,
  Outlook, ChatGPT, Notion and Slack.
- Use app-specific hosts for services such as Gmail and WhatsApp, so unrelated services on the
  parent domain remain eligible for Brovim's dark mode.
- Explain that each site's own dark theme must be enabled. Keep the list editable, preserve an
  existing custom list, and verify that users can save edits or clear the list.

## Current audit fixes — local working changes

1. **Switcher on Brovim's own pages:** allow its Settings/Commands pages to use the same overlay as
   websites. They were incorrectly sent through the protected-page fallback. Test holding the
   modifier without switching and quick taps that immediately activate the previous tab.
2. **New-window navigation:** fix the undefined `tabConfig` reference that crashed every call. Use
   the window API's `focused` field, omit the special new-tab URL, support default searches in the
   new window's actual tab, and return the result. Verify real browser window creation. See the
   [window API](https://developer.chrome.com/docs/extensions/reference/api/windows#method-create).
3. **Search destinations:** target the requesting tab explicitly. Create new search tabs beside the
   source tab in its window. Changing focus while the Vomnibar closes no longer redirects the
   operation to whichever tab/window happens to be active. Return navigation promises so callers can
   await completion. See the
   [search API](https://developer.chrome.com/docs/extensions/reference/api/search#method-query).
4. **Bookmark/history recovery:** clear pending-load promises after failures, allowing later
   requests to retry instead of permanently reusing a rejected promise. Concurrent callers share the
   complete load operation.
5. **Domain suggestions:** count distinct URLs instead of visits. Repeated visits no longer keep a
   deleted domain in suggestions. Ignore removals for untracked/already removed URLs. Coalesce
   concurrent initialization so it installs one listener per history event.
6. **Search-word collisions:** store cached regular expressions without inherited object properties.
   Queries such as `constructor`, `__proto__` and `toString` now receive real regular expressions.
7. **Completion-cache performance:** use Maps and constant-time size checks, and schedule one
   maintenance callback per event turn. Preserve promotion/rotation behavior, handle prototype names
   as normal keys, and make clearing the cache immediate.
8. **Find history:** share pending initialization and await it before saving an early query.
   Register the storage listener once, preserve newer changes received during the initial read, and
   handle a cleared history as an empty list. Private-history behavior remains covered.
9. **Link-hint performance:** request only the top hit with `elementFromPoint` when available,
   retaining a fallback for roots exposing only `elementsFromPoint`. Preserve shadow-root descent
   and loop protection while avoiding unnecessary full hit-stack construction.
10. **UI initialization:** fix the duplicate-load guard's misspelled field and avoid observing a
    nonexistent HTML head on SVG/XML documents.
11. **Numeric settings:** reject empty, nonnumeric, zero or negative scroll sizes before saving.
    Check numeric fields' range limits and display validation feedback without replacing working
    settings or crashing when the input has no following sibling.
12. **Helium setup:** reject `--profile` without a directory, including `save --profile`. It must
    fail instead of silently using or modifying the default profile.
13. **Verification:** add regression tests for these cases, real window creation, Settings-page
    hold/tap switching, and an 18,000-row/1,500-link document. Use a genuinely protected browser
    page for fallback tests. Wait for recovered page controls rather than merely counting an
    initialization request, and allow scheduling slack around the deliberately delayed image.

A separate local edit added `excalidraw.com` to the dark-mode exclusion defaults during this audit.
It was preserved, and the file was formatted with the repository formatter. That edit is listed
separately from the audit fixes above.

## Verification limits

- The separate lifecycle and OS-level native-shortcut suites could not start their local servers:
  the sandbox returned `PermissionDenied` from `Deno.serve`. Their source was reviewed; the table
  above reports the checks that actually ran.
- No Firefox executable was available for a live Firefox run. Its archive/resources were checked.
- Browser-protected pages that forbid extension frames retain direct tab switching. The overlay
  works on websites, excluded sites, Brovim's own supported pages, and Chromium internal pages where
  the developer override permits it. The two-tab direct-swap preference remains available.
- The current audit fixes are local working changes. The two linked commits above were already
  pushed before this audit.
